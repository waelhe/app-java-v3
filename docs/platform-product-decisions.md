# سجل قرارات المنتج — المنصة المجتمعية المحلية

**الحالة:** سجل تأسيسي للقرارات الصريحة والمفتوحة. لا يستبدل كلمة المالك، ولا يحوّل توصية فنية إلى قرار منتج.

## القرارات المثبتة من توجيه المالك

| المعرّف | القرار | الحالة | الأثر |
|---|---|---|---|
| PD-01 | المنتج منصة مجتمعية محلية متعددة الأدوار والوظائف والمزودين على مستوى البلد والمدينة والأحياء، وليس مجرد marketplace أو عميل لواجهات موجودة | معتمد بتوجيه المالك | يحدد نطاق المنتج ورحلاته وأصحاب البيانات |
| PD-02 | لا يُختزل الجوال إلى تغليف للباك إند؛ تُنفّذ الفجوات الخلفية اللازمة لإكمال تجربة المنتج | معتمد بتوجيه المالك | backend الموجود أساس يُعاد استخدامه وتوسيعه بعد القياس، لا سقفًا للنطاق |
| PD-03 | العميل الأول المستهدف Android أصلي؛ Kotlin وJetpack Compose هما اتجاه التنفيذ | معتمد وفق قرار المالك السابق | يجب بناء تجربة أصلية ونظام تصميم، لا WebView أو واجهة API demo |
| PD-04 | «البث الرسمي» المقصود رسائل/إعلانات مؤسسية محلية، وليس livestream فيديو | معتمد وفق توجيه المالك | يتطلب جهة مفوضة ونطاقًا جغرافيًا ودورة نشر/تصحيح/سحب وانتهاء |
| PD-05 | كل تسمية بسيطة لوظيفة تعني رحلة مستخدم كاملة؛ التعليق أو السؤال أو النشر ليست endpoint منفردة | معتمد بتوجيه المالك | معايير القبول تشمل العميل والخادم والبيانات والإشعارات والحالات ذات الصلة |

## قرارات لم تُحسم ولا يجوز افتراضها

| المعرّف | المسألة | القاعدة الحالية | ما يلزم قبل الحسم |
|---|---|---|---|
| PD-06 | اسم المنتج والعلامة والشعار | غير محسوم؛ يمنع استعمال اسم مؤقت على أنه نهائي | اتجاهات تسمية وهوية وفحص السوق والنطاقات والعلامات |
| PD-07 | أول سوق/بلد إطلاق والقواعد القانونية الخاصة به | غير مثبت | قرار سوق، بحث مستخدمين ومراجعة قانونية/خصوصية عند اللزوم |
| PD-08 | المعيار الدقيق للتحقق من العضوية المحلية | لا تُساوى المتابعة الجغرافية بالإقامة المثبتة | سياسة أدلة وحداثة وسحب واعتراض ومراجعة إساءة الاستخدام |
| PD-09 | دورة الإعارة المدفوعة والتسوية والنزاعات | لا تُعرض كميزة متاحة قبل اعتماد دورة المال والقانون والتوفر | قرار المالك ومراجعة مالية/قانونية واختبارات تعارض |
| PD-10 | شراء/دفع/حجز عام مقابل التواصل فقط | لكل مجال عقد مختلف؛ لا ادعاء مسار معاملة غير موجود | fit-gap للعقد الفعلي والمزود وحالات الدفع والإلغاء والاسترداد |
| PD-11 | اعتماد الخريطة ومصادر الأخبار المحلية وحدودها | تصميم مقترح ينتظر fit-gap | مصادر بيانات وترخيصها وتغطيتها وجودتها وخصوصيتها |
| PD-12 | تخصيص «لك» والرتب المتعلمة | قواعد حتمية أولًا؛ لا تعلم قبل خط أساس وتقييم | بيانات كافية ومجموعة اختبار وقياس جودة/تحيز/تكلفة |
| PD-13 | اعتماد التصميم المرئي النهائي | نظام تصميم مقترح، لا علامة/ألوان نهائية | نموذج تفاعلي واختبار استخدام ومراجعة الوصولية |

## قرارات هندسية تحفظية (ليست قرارات منتج)

- إبقاء Spring Modulith modular monolith هو الخيار الأول ما دام يحمي حدود المجالات ويلبي الحمل؛ لا تقسيم إلى microservices قبل دليل تشغيل/فريق/قابلية توسع.
- إبقاء PostgreSQL/PostGIS كخط أساس، وتقييم البحث المتخصص/الوسيط الإضافي عبر benchmark حقيقي قبل اعتماد كلفة تشغيل جديدة.
- اختيار الإصدارات من المصادر الرسمية المستقرة المطابقة للمشروع وقت التنفيذ؛ لا تثبيت أرقام مأخوذة من مقال أو فرع مؤقت.
- لا يُدمج أي PR إلى main ولا يُطلق إصدار دون قرار المالك الصريح.

## آلية تعديل السجل

كل تغيير يذكر المعرّف والقرار السابق والجديد ودليل الحاجة والأثر في الرحلات والتصميم والكود. تُحفظ قرارات «مفتوح» كما هي حتى اعتماد صريح، ولا يُستنتج القرار من وجوده في وثيقة أو PR.
