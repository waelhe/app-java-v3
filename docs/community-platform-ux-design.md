# تصميم تجربة المستخدم ونظام التصميم — المنصة المجتمعية المحلية

**الإصدار:** 1.0 — 2026-10-10  
**الغرض:** تحويل مواصفة الرحلات ([community-platform-user-journeys.md](community-platform-user-journeys.md)، JT-01..JT-19) إلى نظام تصميم قابل للتنفيذ: رموز، مكونات، شاشات، حالات، وقواعد عربية/RTL/وصولية — بحيث يبني المطوّرون ووكلاء الذكاء الاصطناعي واجهة واحدة متسقة طرفًا لطرف، لا اجتهادات متفرقة.  
**علاقة السلطة:** هذه الوثيقة تملك «كيف تبدو الرحلة وكيف تسلك الواجهة»؛ مواصفة الرحلات تملك «ماذا يجب أن ينجزه المستخدم»؛ [الخطة التنفيذية الموحدة](community-platform-execution-plan.md) تملك ترتيب المراحل والبوابات؛ [مرجع المقارنة مع Nextdoor](community-platform-nextdoor-benchmark.md) يشرح سلوك المنتج المعلن وما لا يجوز افتراضه عن البنية الداخلية؛ وتبقى [خطة المطابقة الرسمية](official-compliance-plan.md) المرجع التقني الحاكم. عند أي تعارض: الرحلات تحدد السلوك، وهذه الوثيقة تحدد الشكل، والخطة الموحدة تحدد الترتيب.  
**حالة الوثيقة:** تصميم مقترح لاعتماد المالك وفق بوابة إقرار §32 من مواصفة الرحلات. كل ما هنا مستهدف لا منشور؛ ويخضع كل مكون جديد لـfit-gap مع الكود قبل تنفيذه. سلم الأدلة (رحلات §0.3) يسري على هذه الوثيقة بالكامل.

## 1. لغة التصميم — «محلي موثوق وصادق»

### 1.1 المبادئ الخمسة غير القابلة للتفاوض

1. **الحقيقة قبل الجمال:** اللون والحركة محفوظان لنقل معلومات (المصدر، الحالة، الحداثة، الصلاحية) لا للزينة. أي عنصر بصري لا يحمل معلومة يُحذف.
2. **النطاق دائمًا مرئي:** رأس النطاق الفعّال (حي/مدينة) ظاهر في كل شاشة اكتشاف؛ تغييره مقصود لا صامت (AC-02-02).
3. **الأصل واضح:** كل بطاقة تحمل مصدرها وزمنه ونوعه. المحتوى الرسمي والمجتمعي والمدفوع ثلاث لغات بصرية مختلفة لا تختلط (رحلات §0.2).
4. **العربية أولًا وRTL أولًا:** كل تصميم يبدأ عربيًا RTL ثم يعكس LTR، لا العكس. العربية والشاشات الصغيرة شرط قبول لا تجميل (AC-01-06).
5. **الصدق في كل حالة:** لا حالة نجاح مصطنعة، لا زر وهمي، لا فراغ بلا خطوة تالية (رحلات §0.2 «لا باب ميت»/«لا اختلاق»).

### 1.2 نظام الألوان الدلالي (Semantic Colors)

لوحة الحياد والهوية قرار المالك (D-25)؛ أما **الدلالي** فثابت لا يتغير بلون الهوية:

| الرمز | الاستخدام | ملاحظة التباين |
|---|---|---|
| `official-source` | شريط المصدر المؤسسي للرسائل الرسمية (JT-10) | لون واحد مميز، نص أبيض/غامق ≥ 4.5:1 |
| `community-source` | وسم المساهمة المجتمعية (JT-16 ب) | ثانوي هادئ |
| `paid-marker` | وسم «إعلان» المدفوع (JT-02/JT-05) | دافئ مميز + نص دائم «إعلان»؛ لا يُحقن في ثقة عضوية |
| `trust-verified` | شارة التوثيق (العضوية/الملكية/المهني) | يصاحبه شكل + نص، لا لون فقط (AC-16-03) |
| `stale-warning` | مؤشر تقادم المعرفة المحلية (JT-16) | هادئ غير عدواني + نص «بحاجة تحقق» |
| `success` / `warning` / `danger` / `info` | حالات النتائج والأخطاء القياسية | وفق WCAG 1.4.3 |

قواعد: (أ) تباين النص 4.5:1 والمكونات/غير النصي 3:1 (WCAG 2.2 AA — 1.4.3/1.4.11)؛ (ب) الحالة لا تُنقل باللون وحده أبدًا — شكل + نص دائمًا؛ (ج) الوضع الداكن (Dark Mode) مشتق تلقائيًا من الرموز نفسها — قرار D-23 (التوصية: تفعيله من الإصدار الأول لأن كلفته مع نظام الرموز شبه معدومة).

### 1.3 الطباعة العربية

- **العائلة:** قرار D-22 بين ثلاثة مرشحة مفتوحة المصدر بأوزان كاملة ودعم لاتيني مزدوج: **IBM Plex Sans Arabic** (التوصية — اتساق رسمي عالٍ مع أرقام متوازنة)، **Noto Sans Arabic** (تغطية أوسع للأوزان)، **Cairo** (طابع ودود أكثر). المرجع: fonts.google.com.
- **السلّم:** 12 / 14 / 16 / 18 / 22 / 28 / 36 على شبكة 4pt؛ ارتفاع سطر عربي 1.6–1.7 (الحروف النازلة كـ«ج، ي، ق» لا تُقص — قاعدة `line-height` كافية ومنع قص الأسفل).
- **الأرقام:** قرار D-24 يعرض التقويم (ميلادي أساسي + خيار هجري للعرض الشخصي)؛ التوصية للأرقام: **الغربية (0-9)** في كل البيانات والتواريخ والأسعار لأمان bidi واتساق المحاذاة، مع جواز عرض السياق بالهندية في النص الأدبي فقط.
- **نص ثنائي الاتجاه:** كل حقن نص لاتيني داخل جملة عربية (اسم عمل، رمز عملة) يُحاط بعزل اتجاه (قواعد §7.2).

### 1.4 الكثافة والتخطيط

- موبايل أولًا: تصميم على 375px واختبار إلزامي على 320–390px (AC-01-06)؛ عرض قراءة نصوص طويلة ≤ 600px على الويب/التابلت.
- الشبكة: 4pt لكل شيء (فراغات، ارتفاعات، أيقونات 20/24، هدف لمس ≥ 44×44 — فوق الحد الأدنى AA ‏2.5.8=24px، مطابقًا لتوصية Material 3 وApple HIG).
- الظلال: مستويان فقط (0 مسطح، 1 للبطاقات، 2 للصفائح العائمة) — بيئة حارة، بصمة منخفضة.

## 2. رموز التصميم (Design Tokens) — الصيغة الجاهزة للتسليم

تُسلَّم الرموز بصيغة **W3C Design Tokens Community Group Draft** (مسودة مجتمعية وليست W3C Recommendation) (tr.designtokens.org) في `client/design/tokens.json`، ويُشتق منها ThemeData للجوال. لا يُفترض وجود عميل ويب أو ملف الرموز حتى اعتماد D-17 وبدء موجة M-0. التسمية: `.{group}.{concept}.{variant}.{state}` — مثال `.color.official.source.solid`، `.size.touch.target.min`.

| المجموعة | القيم الأساسية |
|---|---|
| `size.space` | 4 / 8 / 12 / 16 / 24 / 32 / 48 |
| `size.radius` | chip 4 · card 8 · sheet 12 · avatar full |
| `size.touch` | 44×44 أدنى لكل هدف تفاعلي |
| `size.icon` | 20 / 24 |
| `type.ar.scale` | 12/14/16/18/22/28/36 · line-height 1.65 · weight 400/500/600/700 |
| `color.{semantic}` | جدول §1.2 + محايد 9 درجات دافئة |
| `motion.duration` | micro 120ms · transition 200ms · sheet 250ms |
| `motion.easing` | standard (decelerate) · emphasized (spatial) |
| `motion.reduce` | احترام `prefers-reduced-motion` نظاميًا — إلزامي (WCAG 2.3.3 هدفنا AA: بدائل بلا حركة) |
| `elevation` | 0 / 1 / 2 |
| `z-layer` | base / nav / sheet / dialog / toast |

قاعدة تنفيذية: **لا قيمة بصرية خارج الرموز.** أي PR يُدخل قيمة صلبة (hex/px) خارج `tokens.json` يُرفض في المراجعة — القاعدة نفسها التي تجعل الوضع الداكن ممكنًا بلا إعادة تصميم.

## 3. مكتبة المكونات (CMP) — المخزون الملزم

كل مكون أدناه مواصفته الإلزامية: (1) حالاته، (2) نصه العربي الافتراضي، (3) سلوكه في RTL، (4) عقده مع قارئ الشاشة. المكون رقم + اسم = المرجع في كل PR وكل اختبار golden.

### 3.1 الهيكل والملاحة

- **CMP-01 AppShell** — الهيكل العام: TopBar (نطاق + بحث + إشعارات) + منطقة محتوى + BottomNav. الحالات: connected/degraded(offline banner)/authenticated/guest.
- **CMP-02 ScopeHeader** — النطاق الفعّال + زر التغيير. النص: «النطاق: {اسم الحي}». تغيير النطاق = إعادة جلب معلنة لا قائمة قديمة (حالة عابرة #13).
- **CMP-03 BottomNav** — الوجهات الست من رحلات §2.1: الرئيسية، استكشف، إنشاء (+)، السوق، التواصل، المركز الشخصي. الإشعارات أيقونة في TopBar لا تبويبًا (رحلات §2.1 قاعدة المدخل الثابت). أيقونة «إنشاء» مركزية مميزة؛ RTL: الترتيب ينعكس بالكامل.
- **CMP-04 DeepLinkHandler** — حفظ الوجهة عبر الدخول (AC-01-02) وإعادة الفحص عند العودة (AC-11-03).

### 3.2 البطاقات — عائلة لكل مجال

كل بطاقة تحمل إلزاميًا **CMP-12 SourceMeta** و**CMP-11 StatusChip** عند الحاجة:

- **CMP-05 PostCard** (JT-02/03) — صاحب الصفة + وقت + نطاق + نوع الغرض (سؤال/طلب/توصية…) + مقتطف + عدّادات تفاعل. حالات: VISIBLE / HIDDEN / UNAVAILABLE (سُحب — رسالة صادقة وخيار تحديث، رحلات §4.5).
- **CMP-06 OfficialCard** (JT-10) — **بصمة مؤسسية مختلفة جذريًا**: شريط `official-source` باسم الجهة وتفويضها + حالة السريان (نشط/مصحح/مسحوب/منتهٍ) + منطقة التأثير. العاجل: علاجة أعلى بلا انفجار أحمر — «عاجل» نص دائم + أيقونة إنذار. حالات: ACTIVE / CORRECTED / WITHDRAWN / EXPIRED — المنتهي لا يظهر «نشطًا» أبدًا (AC-10-04).
- **CMP-07 KnowledgeCard** (JT-16) — نوع المصدر (رسمي/مجتمعي/غير محسوم) + **CMP-13 FreshnessIndicator** («آخر تحقق: …») + حالة الاقتراح إن كانت قيد المراجعة. لا تُعرض كمعلومة مؤكدة قبل اجتياز السياسة (AC-16-02/03).
- **CMP-08 BusinessCard** (JT-05/06) — الاسم + حالة النشاط + أنواع التحقق الفعلية (CMP-10) + مناطق التغطية + «لا مراجعات بعد» بدل النجوم الوهمية (AC-05-02).
- **CMP-09 MarketCard** (JT-07/08) — سعر/عملة/حالة العرض (نشط/مباع/منتهٍ)؛ المنتهي لا يبدأ تواصلًا (AC-07-02/05).
- **CMP-10 TrustBadge عائلة** — أربعة أشكال مختلفة بالنص الدائم، لا لون فقط: `TB-VERIFY` (عضوية محلية موثقة) / `TB-OWN` (ملكية نشاط) / `TB-REC` (توصية منسوبة) / `TB-REV` (مراجعة مؤهلة) + `OfficialSourceTag` على حدة. الأشكال: درع / مفتاح / إشارة مرجعية / نجمة مؤهلة — مع tooltip نصي كامل لقارئ الشاشة يشرح «ما الذي يثبته هذا وما لا يثبته» (رحلات JT-12 §14.3 الفصل الضروري).
- **CMP-11 StatusChip عائلة** — الحالات الثماني من رحلات §2.3: منشور / مسودة / بانتظار مراجعة / مخفي / مصحح / مسحوب / منتهٍ / غير متاح لك. المجهول لا يُعرض «نشطًا».
- **CMP-12 SourceMeta** — المصدر + الوقت النسبي المطلق عند التحويم + النطاق. إلزامي على كل بطاقة (رحلات §2.2).
- **CMP-13 FreshnessIndicator** — «آخر تحقق {تاريخ}» أو «بحاجة تحقق» بعلاجة `stale-warning` هادئة (AC-16-07).
- **CMP-14 PaidLabel** — «إعلان» نص دائم + إطار مميز؛ لا يدخل ترتيبًا عضويًا ولا ثقة (AC-02-04/AC-05-05).

### 3.3 الحالات العابرة — مكتبة المواقف الستة عشر

ترجمة مباشرة لحالات رحلات §24 — كل واحدة مكون واحد موحد لا اجتهاد لكل شاشة:

- **CMP-15 LoadingView** — skeleton متطابق شكلًا مع المحتوى (لا سبينر عام فوق فراغ) + منع تكرار الزر نفسه.
- **CMP-16 EmptyView** — سبب مفهوم + **خطوة تالية واحدة** (لا بيانات تجريبية، لا فراغ صامت — AC-01-07).
- **CMP-17 ErrorRetryView** — «أُرسل / لم يُرسل» صراحة + زر إعادة + بقاء المدخلات غير الحساسة.
- **CMP-18 OfflineBanner** — شريط أعلى دائم أثناء الانقطاع + مسودة محلية آمنة حيث ينطبق.
- **CMP-19 SessionExpiredDialog** — إعادة دخول مع عودة للوجهة إن بقيت مصرحًا بها.
- **CMP-20 ForbiddenNotice (403)** — يشرح الصلاحية المطلوبة دون كشف بيانات المورد المحمي.
- **CMP-21 NotFoundView (404)** — لا تمييز «خاص» عن «غير موجود» حيث يقتضيه عقد الأمان.
- **CMP-22 ConflictSheet (409)** — يعرض الحالة الجديدة ويطلب قرارًا، لا يكتب فوق تحديث آخر.
- **CMP-23 RateLimitNotice (429)** — «أعد المحاولة بعد {مدة}» بلا حلقة تكرار.
- **CMP-24 ProviderUnavailableView (5xx/AI)** — fallback معلن: «تعذر المساعد الآن — نتائج البحث التقليدية متاحة» (AC-04-05).
- **CMP-25 EndedContentBanner** — المحتوى المنتهي/المسحوب: توضيح + منع الفعل القديم.
- **CMP-26 SensitiveConfirm** — تأكيد الأفعال الحساسة (سحب/حذف/تصحيح رسمي) بنتيجة مسجلة وقابلة للرجوع حيث يسمح.
- **CMP-27 ScopeChangeNotice** — تغيير النطاق = ترويسة تتغير + نتائج تُعاد (حالة #13).
- **CMP-28 StaleInfoCard** — معرفة محلية متقادمة: حالة القدم + مسار التحقق + زر «أبلغ أنها قديمة» (AC-16-07).
- **CMP-29 DirectionSafeText** — عارض النص العربي/المختلط بقواعد bidi (§7.2) — يُستخدم في كل عرض نص من مصدر خارجي.
- **CMP-30 DateLocaleText** — تاريخ/وقت ميلادي (+هجري إن D-24) بتوقيت المنطقة المعلنة (AC-09-04).
- **CMP-31 NetworkRetryGuard** — حماية idempotency على مستوى الواجهة: منع الإرسال المزدوج أثناء الانتظار (AC-03-02/AC-07-04).
- **CMP-32 KeyboardAvoidPanel** — لوحة المفاتيح لا تغطي حقل الإدخال الفعّال ولا زر الإرسال (اختبار إلزامي على 320px).

### 3.4 التدفقات الوظيفية

- **CMP-33 Composer** — الإنشاء يبدأ بمفتاح الغرض (UJ-20): سؤال/طلب/توصية/استطلاع/مفقودات/إعلان/فعالية — ثم محرر بحقول النوع. المعاينة تظهر الصفة والنطاق قبل النشر (رحلات JT-03 §5.2.4).
- **CMP-34 FilterSheet** — فلاتر لكل عمودي (عقار/مركبة/وظيفة…) مطابقة للبيانات الفعلية لا سمات وهمية (AC-08-04).
- **CMP-35 ScopeSelector** — البحث الجغرافي الملتبس يعرض خيارات صريحة، لا تحويلًا صامتًا للمدينة/البلد (AC-02-02، رحلات JT-04 §6.2.2).
- **CMP-36 VerificationFlow** (JT-12) — ثلاث شاشات: ما يثبته هذا التوثيق / الأدلة المطلوبة وسياسة ظهورها / الحالة + مسار الاستكمال الآمن. لا مستند في سياق عام.
- **CMP-37 ReportFlow** (JT-13) — سبب + تفاصيل دنيا + رقم بلاغ + «بلا وعد مسبق بنتيجة» + متابعة حالة بلا كشف هوية المبلّغ (AC-13-02).
- **CMP-38 DataRightsPanel** (جديد من فجوات المراجعة) — تصدير بياناتي (مهمة غير متزامنة + تنزيل موقّت) / تصحيح / حذف الحساب والإغلاق مع بيان أثر المحتوى المتبقي وفق سياسة الاحتفاظ (قرار D-20). مواصفة الواجهات الخلفية في ملف الباك-إند §9.
- **CMP-39 DigestSettings** (جديد) — وضع تجميع استفسارات صاحب العمل: فوري / ملخص يومي / هادئ. يمنع طوفان الإشعارات (فجوة P5، رحلات JT-06).
- **CMP-40 NotificationPrefsPanel** — تفضيلات النوع/القناة مع **معاينة التفضيل الفعّال** (AC-11-05) وفرق القنوات (رفض push ≠ إيقاف الصندوق الداخلي — رحلات JT-01 §3.5).
- **CMP-41 AgeGate** (إن اعتمد D-19) — بوابة عمر + مسار أهلية الوالدين حيث توجب السياسة.
- **CMP-42 MapViewport** (JT-18) — إطار الخريطة وScopeHeader وطبقات/علامات/تجميع؛ يُظهر النطاق الحالي ويحوّل «ابحث في هذه المنطقة» إلى فعل صريح، ولا يجعل الإحداثيات دليل عضوية. يجب أن يقترن بقائمة نصية بديلة وحالات إذن مرفوض/مصدر فاشل/علامات متقادمة.
- **CMP-43 LocalNewsCard** (JT-19) — اسم الناشر ونوع المصدر ووقت النشر/التحديث والرابط الأصلي وحالة التصحيح/السحب؛ يفصل رابط عضو عن مادة ناشر معتمد وعن رسالة رسمية/تنبيه عاجل، ويعلن إن كان النص ملخصًا مولدًا مع روابط الأدلة.

كل مكون أعلاه: اختبار golden إلزامي بحالتين (RTL + LTR) وبحالاته كاملة قبل اعتماده — راجع ملف الجوال §4 و§12 هنا.

## 6. العربية وRTL — قواعد التنفيذ الملزمة

### 6.1 البنية

- الاتجاه مصدر واحد: `directionality` عربي في جذر التطبيق؛ LTR اتجاه عرض معكوس كامل (لا إصلاحات موضعية).
- الأيقونات الاتجاهية (سهم «رجوع»، «التالي»، فتح الدرجة) تنعكس مع الاتجاه؛ الرموز المحايدة (تشغيل، ساعة، إبلاغ) لا تنعكس — قائمة معتمدة لكل أيقونة في `tokens.json`.

### 6.2 bidi — النص المختلط

1. نص لاتيني/أرقام داخل جملة عربية ⇒ عزل اتجاه بمحارف Unicode المعيارية (LRI/RLI/FSI) أو مكافئ المنصة — التطبيق عبر **CMP-29** حصرًا، لا يدويًا في كل موضع.
2. أرقام هواتف وعملات ورموز تعرض LTR داخل سياق RTL مع عزل — مواضعها في `DirectionSafeText` مختبرة بثلاث عينات على الأقل (اسم لاتيني، رقم هاتف، تاريخ مختلط).
3. حقول الإدخال: `textDirection` يتبع لغة أول حرف مع قواعد محاذاة RTL — سلوك موحد عبر المنصة (قرار التنفيذ في ملف الجوال §3).

### 6.3 التواريخ والأزمنة

- ميلادي أساسي بصيغة عربية موحدة («12 أكتوبر 2026» + الوقت بتوقيت المنطقة المعلنة)؛ خيار عرض هجري شخصي (D-24) عبر منصة intl المعيارية (ECMA-402/ar-SA-u-ca-islamic).
- الوقت النسبي («قبل ساعتين») بحذار: يُعرض نسبيًا في البطاقات والمطلق عند التحويم/قارئ الشاشة — مع تحديث عند تجاوز عتبة الدقة.

### 6.4 الإدخال العربي والبحث

- حقل البحث: عرض توحيد الألف/الهمزة/الياء/التشكيل بشفافية («بحثك شمل: …») لا تصحيحًا صامتًا (AC-04-03 ينطبق على الواجهة والخلفية معًا).
- لوحة مفاتيح عربية افتراضية للحقول العربية (`lang="ar"`) وإعدادات لغة الحساب (إن D-18) تتبع تفضيل المستخدم لا موقع الـIP.

## 7. الوصولية — هدف WCAG 2.2 AA وخطة إثبات المطابقة

المرجع المعياري هو [W3C WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/). **هذا هدف قبول، وليس ادعاء مطابقة حالية.** النقاط التالية حواجز رئيسية وليست قائمة كاملة بديلة عن مصفوفة معايير النجاح المنطبقة على كل شاشة وعملية كاملة.

- **1.4.3 Contrast (Minimum):** تباين النص العادي 4.5:1، مع الاستثناءات المعرّفة في WCAG؛ **1.4.11 Non-text Contrast:** 3:1 للمكونات والحالات المرئية التي يشملها المعيار. اختبار الرموز آليًا وفحص التركيبات الفعلية يدويًا.
- **2.4.7 Focus Visible:** مؤشر تركيز لوحة المفاتيح ظاهر. **2.4.11 Focus Not Obscured (Minimum):** لا يحجب محتوى أنشأه المؤلف العنصر ذا التركيز بالكامل. لا يُستخدم أحدهما بديلًا عن الآخر.
- **2.5.8 Target Size (Minimum):** يطبق حد المعيار والاستثناءات؛ هدف التصميم الداخلي 44×44 CSS px حيث يلائم، بوصفه هدفًا أعلى لا نصًا حرفيًا من WCAG.
- **3.3.7 Redundant Entry:** لا يُطلب تكرار بيانات أدخلها المستخدم في الرحلة نفسها إلا ضمن استثناءات المعيار. **3.3.8 Accessible Authentication (Minimum):** مصادقة يمكن إتمامها دون اختبار معرفي غير مسموح به، مع الاستثناءات والطرق البديلة المعيارية.
- **4.1.2 Name, Role, Value** و**4.1.3 Status Messages:** المكونات والحالات قابلة للإدراك بتقنيات المساعدة، ولا تعتمد الحالة على اللون وحده.
- **2.3.3 Animation from Interactions** مستوى **AAA**؛ يمكن تبنيه كتحسين إضافي مع احترام تفضيل تقليل الحركة، لكنه ليس معيارًا مطلوبًا ضمن AA.
- تُنشأ مصفوفة امتثال كاملة: المعيار المنطبق ← الشاشات والعمليات ذات الصلة ← طريقة الإثبات ← نتيجة الاختبار ← الاستثناء المبرر إن وجد. النجاح الآلي وحده لا يثبت المطابقة.
- أدلة القبول تجمع اختبارات وصولية آلية، ومراجعة يدوية للتباين والتركيز والتكبير وترتيب القراءة، واختبارات قارئ الشاشة، وRTL/LTR، ولوحة المفاتيح. يُختبر سير المهمة الكامل، لا الشاشة المفردة فقط.

لا تُكتب عبارة «WCAG 2.2 AA compliant» قبل اجتياز المصفوفة على الإصدار النهائي للرحلات/الشاشات المعنية ومراجعة كل الاستثناءات المعلنة.

## 9. إشعارات ورسائل — أنماط الواجهة

- **شاشة القفل:** نص مقتضب محايد بلا محتوى حساس («لديك رسالة جديدة من {اسم}») — السياسة في كتالوج رحلات §27.

- **Quiet hours:** قرار D-26 (التوصية: 21:00–07:00 بتوقيت المستخدم، يجوز تجاوزها للعاجل الرسمي فقط وفق سياسته).
- **منع التكرار البصري:** وصول الحدث مرتين لا يظهر إشعارين (idempotency خلفي + مفتاح عرض في الواجهة — AC-10-05/AC-11-02).

## 10. برامج الإطلاع البارد وأول أسبوع (سد فجوات المراجعة)

### 10.1 إقلاع الحي البارد (قرار D-21)

### 10.2 حلقة الأسبوع الأول

## 12. التسليم للتنفيذ (Handoff)

1. `client/design/tokens.json` (صيغة DTCG Draft) — مصدر الرموز الوحيد؛ CI يتحقق عدم وجود قيم صلبة خارجه في كود الواجهة.
2. مواصفة كل مكون CMP كقسم في هذه الوثيقة هي العقد — أي تغيير يمر عبر PR توثيقي يشير لرقم المكون.
3. اختبارات golden (RTL+LTR+حالات) لكل مكون قبل أول استعمال — لا يُبنى مكون ثانٍ قبل أن يخضر أول اختبار.
4. ترتيب البناء يتبع موجات ملف الباك-إند §12 والجوال §9 — لا شاشة قبل جاهزية عقدها الخلفي.
5. كل شاشة تنجز تُسجل في تقرير قبول الرحلة (رحلات §34.1) مع لقطة golden ونتيجة 320px/RTL/قارئ شاشة.
