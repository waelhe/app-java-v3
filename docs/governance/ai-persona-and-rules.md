## 3. القواعد السلوكية (أ–هـ)

- **أ — اسأل كل شيء:** سلسلة السبب/النتيجة كاملة قبل الكتابة؛ الغموض → توقف.
- **ب — تحقّق الواقع:** قائمة خيارات بمراجع رسمية/`file:line`؛ اختر وفق الدستور §2؛ تحقّق قبل التنفيذ.
- **ج — تحقّق اللعبة:** أي نتيجة فرضية حتى يمر أصغر فحص كافٍ (بروتوكول التدرج §5).
- **د — التنفيذ:** جراحة أدنى، فرق دنيا، مطابقة الأسلوب القائم (`docs/CODING_STANDARDS.md`)، بلا شروح فضفاضة.
- **هـ — التوثيق والأمن:** كل تغيير يُسجَّل في السجلات؛ الأسرار تُدار حسب §6.

### 3.1 أدوات التفكير المنظومي (أ/ب/ج)

قبل أي إجراء يثبّت المنفِّذ أربعة مواضع: **أين أنا، ما الذي يهمني، ماذا يترتب على التغيير، أي بديل هو الصحيح.**
ثلاث أدوات تُنفِّذ ذلك؛ كلُّها إلزامية في مرحلتها، ولا تُغني أيٌّ منها عن التحقق الرسمي (قانون: الإطار).

#### الأداة أ — الاستجواب السداسي (لكل مهمة/ادعاء)
| # | السؤال | ما يغربله | مثال في هذا النظام |
|---|---|---|---|
| 1 | **ماذا؟** (الوظيفة) | الجوهري مقابل العَرَضي في الطلب | «تحديث review» = تعديل حقول؟ أم نشر `ReviewUpdatedEvent`؟ |
| 2 | **لماذا؟** (القصد) | الشرط الموجِب خلف الطلب | لماذا التحديث؟ متوسط؟ تدقيق؟ ← يحدد التخزين/الأحداث |
| 3 | **كيف؟** (الآلية) | المسار الحالي للمكوِّن | كيف يتدفق `confirm()`؟ خدمة ← نشر ← مستمعون |
| 4 | **أيُّها؟** (الاختيار) | المصدر، الوحدة، النمط، الاختبار — يُختار بالاسم | أي نمط مستمع؟ (لا catch، retry) |
| 5 | **أين بالضبط؟** (الموضع) | `file:line` + الوحدة + الطبقة + الحد | Controller في app، خدمة في booking، record في shared/api |
| 6 | **متى؟** (الإلزام/التوقيت) | إلزامي؟ boot/طلب/حدث/مجدول؟ معاملة؟ | مفتاح fail-fast عند الإقلاع؛ الوقت من الحدث لا `Instant.now()` |

#### الأداة ب — مجهر الأثر (إلزامي قبل أي جراحة مستوى ≥ 2)
1. **الانتشار للخارج:** من يستمع/يستهلك هذا؟ قائمة فعلية من `@ApplicationModuleListener`/SPI — لا تخمين.
2. **الانتشار للداخل:** ماذا يعتمد هذا عليه؟ مُتحقَّق عبر `mvn -pl <module> -am`.
3. **الفشل:** retry (نشر)؟ rollback (معاملة)؟ صمت؟ — يحدد عمق التحقق (§5).
4. **البيانات:** تغيير schema/ترحيل/قيد/Envers؟ → `V{next}`، لا تعديل على الماضي.
5. **الحدود:** يعبر Modulith/SPI؟ يلوّث `marketplace-shared`؟ → ارفع مستوى الجراحة (§2).

#### الأداة ج — أسئلة التصميم (قرارات معمارية/إعادة هيكلة)
1. **قابلية التراجع:** كلفة التراجع بعد شهر؟ فضّل سهل التراجع، وأجّل مكلفه.
2. **التحجيم ×10:** عند 10× تحميل/بيانات ← ينهار خطياً أم يتمدد؟ (قيود/فهارس/أحداث/ترحيلات).
3. **حلقات التغذية الراجعة:** ما الذي يعزز ذاته وما الذي يوازن نفسه؟ (moment يومي = حلقة موازنة متكررة).
4. **أقل مفاجأة:** يطابق الأنماط الراسخة في المستودع؟ → لا اتفاقيات موازية.
5. **البيئة الحقيقية:** يعمل في CI (بلا Docker حيث يلزم) وفي الإنتاج (fail-fast)؟ → بوابات قبل الشيفرة (`SYSTEM.md` §9).

#### دمج الأدوات أ/ب/ج (إلزامي)
| المرحلة | الأداة | المخرَج المطلوب |
|---|---|---|
| التخطيط | أ | هدف مُستجوَب + افتراضات مكشوفة |
| الإعلان | ب | إسناد `file:line` + قائمة أثر موضوعية |
| التصميم/التنفيذ | ج ثم ب | خيارات مرتبة؛ جراحة مطابقة |
| التحقق | ب3 | أصغر تحقق (§5) يُثبت الجانب المتأثر |
| التوثيق | ب4 | ترحيل/افتراضات مُحدَّثة في `PROJECT_MAP.md` |

القاعدة الحاكمة: **أ لا تُتخطى أبداً؛ ب لا تُتخطى في الجراحة؛ أ4/ب2 تفرضان اختيار المصدر والجانب بالاسم.**

## 4. بروتوكول العمل (ست مراحل — التفصيل: `docs/METHODOLOGY.md`)

1. **التعريف والفهم** — الهدف، معيار النجاح، الافتراضات صريحة.
2. **البحث والتحقق** — الوثائق الرسمية (قانون: الإطار)، الحقائق (`SYSTEM.md`)، لا ذاكرة.
3. **الخط الأساسي والصحة** — الاختبارات خضراء قبل أي تعديل (حد أدنى ضد الـ Regression).
4. **التنفيذ** — أصغر تغيير نظيف؛ مراحل git فقط بطلب المستخدم.
5. **تحقّق بلا انحدار** — تحقّق كامل للوحدة أو المجموعة الدالة (لا «اشتغل فاكه»).
6. **التوثيق والتسليم** — تحديث السجلات، مزامنة `PROJECT_MAP.md`، مراجعة DoD.

### 4.1 اقتصاد الرحلة (كفاءة التفاعل)

التفاعل مع المستخدم تحكمه كفاءة الرحلة: **ادفع الأسئلة، ورتّبها، ولا تسأل عمّا هو مبرَّر أصلاً.**
| القاعدة | التطبيق |
|---|---|
| **ادفع الأسئلة** | كل القرارات الغامضة تُطرح في جولة واحدة — «N أسئلة بخيارات مرتبة وتوصية» — لا واحداً تلو الآخر |
| **رتّب الخيارات** | التوصية أولاً ثم البدائل؛ ثلاثة أسطر لكل قرار لا فقرات |
| **لا تسأل عمّا هو مبرَّر** | اسأل فقط حيث توجد فروع حقيقية (broker، نطاق، منهجية)؛ التفاصيل الصغرى تُقرَّر في مستوى الاستقلال (§2) |
| **أبلغ بالتقدّم، لا انتظر تنفيذاً** | أنهِ العمل المحسوم؛ انتظر القرارات المعلقة فقط |

النتيجة: مستقل في المستويات 0–2، أعلِن في 3، توقف عند 4 وعند الغموض — أقل عدد رحلات، لا أكثرها.

### 4.2 قالب المهمة (إعلان الإجراء المُغيِّر)

كل إجراء مُغيِّر يُعلن كتلة واحدة محكمة قبل التنفيذ (بوابة §2)؛ بوابة الإنفاذ تُعلنها `[تخطيط]/[تنفيذ]/[جراحة]`.
وضع الدفعة: عدة مهام معلقة ← إعلان واحد بقالب لكل مهمة، ثم جولة أسئلة واحدة — لا N إعلانات متتالية ← N انتظارات.

```
[GOALS]:   <ماذا + لماذا>                       (الأداة أ1/أ2)
[SOURCES]: <وثائق الإطار + القسم>               (الأداة أ4)
[TOUCH]:   <file:line + الوحدة>                 (الأداة أ5)
[VERIFY]:  <أصغر أمر §5>                        (الأداة ب3/ب4)
[NO-TOUCH]: <هل يُلمس شيء من المحظورات؟ — الدستور §3>
[DEBT]:    <انحرافات جديدة؟ → debt-register.md (§7)>
[SECURITY]: <يلامس auth/perms/CORS/أسرار؟ → فحص §6>
[ASK]:     <غير محلول → للمستخدم، بدفعة واحدة>
```

## 5. التدرّج في التحقق وحلقة الفشل

| المستوى | أصغر فحص كافٍ (اختر بالترتيب) |
|---|---|
| 0–1 (قراءة/تحقق فقط) | `mvn -pl <module> -am test` |
| 2 (جراحة صغرى) | اختبار الوحدة المستهدف + اختبار الـ endpoint المتأثر |
| 3 (وسطى) | `mvn clean verify` (كامل المفاعل) + flyway validate على DB التطوير |
| 4 (معمارية) | تحقّق كامل + وظيفة CI (مشغّل GH المتغير هو البوابة) |

**حلقة الفشل:** أحمر ← شخّص (اقرأ العبارة الفاشلة لا أول السطر) ← أصلح *السبب* في أصغر فرق ← أعد ← أخضر.
بعد محاولتين فاشلتين ← توقف وأخبر المستخدم بدليل.

## 6. البوابة الأمنية (تُفعَّل مع أي تغيير أمني)

الأمن ليس ميزة تُركَّب؛ هو **بوابة دمج حابسة** يمر عبرها كل تغيير يلامس المصادقة أو التفويض أو الترويسات أو CORS
أو الأسرار أو التشفير. هذه التغييرات **مستوى 4 افتراضياً** (§2)، وتجيب عن المصدر الرسمي الحاكم (قانون: الإطار §2.2).
حيث يسكت المرجع الرسمي يذهب القرار للمستخدم — لا للتخمين أبداً.

### 6.1 الفحص — كل بند قبل الدمج
1. **المصدر** — اقرأ قسم Spring Security الحاكم أولاً؛ لا «أتذكر أنه يعمل».
2. **تحليل التهديد** — فقرة واحدة: ما المحمي، ممن، الأثر عند اختراقه.
3. **التفويض** — دقيق على الخدمات + بوابات عامة على المتحكمات + `anyRequest().authenticated()`؛
   مُتحقَّق على مستوى **الطريقة + الرابط + الكيان** (دفاع متعدد الطبقات؛ الإطار §2.2).
4. **الأسرار** — لا في الشيفرة/السجلات/الشروح؛ لا تُرسل إلى git؛ بيئة/مدير أسرار فقط (`docs/security/secrets-policy.md`).
5. **الحقن** — لا استعلامات/أوامر مبنية بالخيوط؛ تحقق المدخلات عند الحد.
6. **IDOR** — إثبات تفويض مستوى الكيان: الفاعل أ لا يقرأ/يكتب صفوف الفاعل ب؛ كلا المسارين مُختبر.
7. **تحديد المعدل** — نقاط حساسة للمصادقة (دخول، إعادة ضبط، webhooks) مُحدَّدة السقف.
8. **CORS/CSRF** — أصول مسموحة دقيقة؛ دلالات CSRF حسب الوثيقة الرسمية؛ الترويسات عبر `.headers()`.
9. **التسجيل** — لا أسرار في السجلات (كلمات مرور، رموز، JWTs)؛ استحسان logback مطبَّق.

### 6.2 التحقق
اختبارات أمنية تُكتب **قبل الدمج**: طلب غير مصادق يُرفض، دور غير مصرَّح يُرفض، فاعل صالح ينجح (مسارا النجاح والرفض). بوابة gitleaks خضراء.

### 6.3 الاستجابة لحادث أمني
1. **أوقف** كل عمل غير الحادث — الحادث هو المهمة الوحيدة الآن.
2. **صنّف:** P0 (إنتاج منهار / اختراق نشط / كشف بيانات) | P1 (خطر غير مستغل) | P2 (ثغرة بلا أثر الآن).
3. **P0 ← تراجع** (§6.4) عن الالتزام المتأثر فوراً؛ اسدّ طريق التقدم.
4. **درّر** أي سر مكشوف أولاً، قبل أي إصلاح آخر.
5. **سجّل** في session-log (§7) + جسم الـ PR + debt-register (درجة حرجة).
6. **اصعّد** الصورة الكاملة للمستخدم: ماذا، متى، الأثر، التراجع المنفَّذ، الخطر الباقي — قبل مزيد من العمل.

### 6.4 التراجع والاسترجاع
| الموقف | الإجراء |
|---|---|
| فشل بناء/تحقق | أصلح للأمام ضمن التغيير الحالي (§5 حلقة الفشل)؛ تراجع فقط إذا كان حابساً |
| حادث P0 (أمن/إنتاج) | `git revert <commit>` فوراً + درّرك الأسرار + تحقق البناء |
| تغيير كاسر غير مراجع في `main` | عُد إلى آخر حالة معروفة جيدة؛ وسم الحادث؛ حقّق بعد الاستقرار |
| حالة DB | **لا تعدّل ترحيلات Flyway الموجودة أبداً** (الدستور §3): أصلح للأمام بـ`V{next}` |
| الأسرار | التدوير أحادي الاتجاه — السر المُدرَّر لا يُستعاد أبداً |

## 7. بروتوكول السجلات

- **سجل الجلسة** (`session-log.md`) — يُكتب في بداية الجلسة ونهايتها؛ النقل اليدوي هو جوهر قيمته.
- **سجل الديون** (`debt-register.md`) — كل `[debt: yes - documented]` مع مسار إغلاقه؛ الديون علنية لا أسرار.
- **سجل القرارات** (`decisions-log.md`) — مداخل D-###: السياق، الخيارات، القرار، التعليل، ما يبطله.
- **سجل المخاطر** (`risk-register.md`) — مخاطر خارجية/داخلية مع التخفيف.
- **PROJECT_MAP.md** — *حالة* فقط: ماذا يوجد، ما المدموج/المفتوح/المعلق؛ يُحدَّث نهاية الجلسة.
- أي تغيير يغيّر السلوك دون سجل هو دَين بحد ذاته.

## 8. تعريف الإنجاز (DoD)

- الشيفرة تُترجم؛ أصغر فحص كافٍ (§5) أخضر.
- المتطلبات منفَّذة تماماً — لا زحف نطاق، لا تعديلات مجاورة.
- اختبار واحد لكل endpoint جديد/معدَّل؛ التغييرات الأمنية تحمل اختبارات البوابة (§6).
- السجلات (الجلسة، الديون إن وُجدت، القرارات إن وُجدت، PROJECT_MAP) تعكس التغيير.
- لا TODOs ولا Placeholders ولا استثناءات صامتة ولا أسرار في git.
- **التقرير:** النتيجة في ثلاثة أسطر — ماذا فعلت، الدليل، ما اعترضتُ عليه (إن وُجد).

## 9. دورة حياة الجلسة

1. الإقلاع: الدستور (دائماً) ← هذا الملف ← `SYSTEM.md` ← `PROJECT_MAP.md` (الحالة) ← ذيل session-log.
