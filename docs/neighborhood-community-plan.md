# خطة الطبقة المجتمعية المحلية — نحو مستوى Nextdoor (الطبقات 41+)

> **الحاكمة لبناء طبقة المجتمع المحلي فوق البنية القائمة.** مُصمَّمة بأمر المستخدم (2026-09-14): «كيف يصل التطبيق لمستوى تطبيق Nextdoor، صمم خطة مستندة للوثائق وتلتزم الاطار، +؛نفذ البوابات المعلنة، واستند للوثائق الرسمية للاطار مايفين وغيرهم, وتفعيل مراجعات CodeRabbit… لا اريد ماتراه انت صحيح اريد التصميم الرسمي حسب الاطار والنظام وحقائق من الكود».
>
> **النمط:** هذه الخطة السادسة تكمل عائلة الخطط الحاكمة (الأمن `docs/security/auth-system-redesign-plan.md`، العملاء والاستضافة، التوسع `docs/feature-expansion-roadmap.md`، أنظمة العقار `docs/realestate-systems-plan.md`، PostGIS `docs/postgis-integration-plan.md`) — وتُبنى فوق حالتها النهائية المقيسة: مسار F مكتمل 11/11، بوابات I7 مقفلة، الطبقات 30-33 مدمجة (PRs #297/#299)، P1-P3 من PostGIS مدمجة (آخرها فصل هويات P3 + V51 بوصولها للإنتاج)، حادثة بصمة V51 مسدَّدة بحارس آلي (PR #310/#311 — main = `400d008`)، والإنتاج يخدم `38b612bb` بـ52 ترحيلة سليمة التحقق. ترقيم الطبقات يكمل سلسلة SYSTEM.md §11 (خطة العقار حجزت 34-40؛ هذه تبدأ 41).
>
> **المرجعية المستهدفة (قياس القدرات لا الاستنساخ):** «مستوى Nextdoor» هنا مثل «مستوى Airbnb» في خارطة الإغلاق السابقة — مرجع منتج ظاهر يُقاس عليه طقم القدرات لا اسمٌ يُقلَّد. طقم Nextdoor العام المقيس إلى قدراته الثماني الظاهرة: **عضوية الحي** (انتماء موثَّق لمجتمع محلي جغرافي) / **تغذية الحي** (منشورات مصنفة + تعليقات) / **التوصيات والأعمال المحلية** (طلب/تقديم توصية لخدمة محلية) / **الرسائل المباشرة بين الجيران** / **الإشعارات المصنفة** (تفضيل لكل نوع وقناة) / **الإشراف والسلامة** (تقارير + طابور إشراف + إخفاء) / **العقار في سياق الحي** (المعروضات داخل تغذية المجتمع) / **المجموعات**. الجدول في §0 يقيس كل واحدة أمام الواقع — لا استنساخ واجهات ولا تخمين منتج؛ ما ليس في هذا الطقم لا يُبنى.

**الوثائق الرسمية المعتمدة (مقيسة هذه الجلسة، مخبأة):**

- **Spring Modulith — «Working with Application Events»** (`scripts/modulith-events.html` مخبأة، مقيسة نصيًا): `@ApplicationModuleListener` هو «shortcut» الذي يوفره الإطار لما يصفه بـ«the default way of integrating modules via events» — مستمع غير متزامن معاملي بـ`@TransactionalEventListener` + `REQUIRES_NEW`؛ وسجل نشر الأحداث (Event Publication Registry) «hooks into the core event publication mechanism of Spring Framework… writes entries for each of them [listeners]» وعند فشل المستمع «the log entry stays untouched so that retry mechanisms can be deployed» — هذا الأساس الرسمي لكل تكامل عابر للوحدات في هذه الخطة (إشعار الجيران بمنشور/لوحة جديدة، إخفاء بإشراف).
- **Spring Data JPA 4.1.1 — Specifications** (الاقتباس الرسمي المقيس في §0 من الخطة الرابعة): «extensible set of predicates… removing the need to declare a query (method) for every needed combination» — أساس استعلامات التغذية والفلاتر.
- **Flyway — الترقيم النسخي V** (`scripts/doc-verify/flyway.html` مخبأة): كل تغيير مخطط ملف V جديد؛ لا تُعدَّل ترحيلة موجودة أبدًا (قاعدة AGENTS — وسجل حادثة البصمة §15: الترحيلة المطبَّقة تجمَّد بايت-بايت).
- **PostgreSQL — الفهارس الجزئية والتعبيرية** (قياسات البيت V7/V34/V47): فهرس فريد جزئي `WHERE booking_id IS NULL AND is_deleted = false` على زوج المشاركين المرتب تعبيرِيًا (`LEAST/GREATEST`) هو الآلية الرسمية لتفريد المحادثات المباشرة بلا عمود تمييز جديد.
- **قواعد AGENTS.md الإجبارية**: كل كيان `@Audited` + كل اختبار إدماج `@ActiveProfiles("test")` + `@Testcontainers(disabledWithoutDocker = true)`.
