## 1. المبادئ المعمارية الحاكمة (غير قابلة للتفاوض)

1. **Modulith لا مايكروسيرفس:** التطبيق مفاعل واحد بحدود وحدات مفروضة باختبارات Spring Modulith القائمة (رسميًا: docs.spring.io/spring-modulith/reference). فريق صغير + وكلاء AI + نشر Railway = المفاعل الواحد أرخص وأصدق. أي اقتراح «استخراج خدمة» يحتاج ADR يثبت فشل الحل داخل المفاعل أولًا.
2. **مصدر حقيقة واحد + إسقاطات:** كل حقيقة أعمال يملكها مجال واحد (جدول §2). التغذية والبحث والبطاقات إسقاطات تحمل `source-id + source-type + version/updated-at` وتعيد فحص المصدر عند الفتح والتنفيذ (رحلات §25.1). الإسقاط لا يقرر الحقيقة النهائية أبدًا.
3. **fit-gap قبل أي enum/جدول/سير عمل جديد:** مفردات الحالات في مواصفة الرحلات **دلالية مستهدفة** لا أوامر تنفيذ — تُطابق مع المقيس ثم تُوسع بترحيل آمن (رحلات §3.3 صراحة).
4. **الأحداث عبر حدود Modulith فقط:** لا استدعاء مستودع متقاطع بين الوحدات — عقد SPI في `marketplace-shared` وأحداث Spring Modulith (رسميًا: docs.spring.io/spring-modulith/reference/events.html) مع مستهلك مالك وidempotency عند الاستهلاك.
5. **تعريف العملية قبل الكود، ووصف API مولّد بعد تحديث الكود:** يُتفق على سلوك العملية وDTOs وحالاتها ضمن PRD/AC قبل التنفيذ. بعد تعديل controller/DTO يولد springdoc وصف OpenAPI من الكود، وتختبر بوابة التوافق الرجعي الحالية عدم كسر المستهلكين؛ لا تُدار نسخة YAML ثانية يدويًا. تغييرات الكسر تحتاج إصدارًا/قرارًا معلنًا.
6. **الأخطاء عقدًا:** RFC 9457 `application/problem+json` موحدًا (رسميًا: rfc-editor.org/rfc/rfc9457) — عنوان وسبب وحالة HTTP متسقة عبر كل الوحدات؛ الواجهة تبني عليها مكتبة CMP-15..24.

## 3. استراتيجية عقد API — تصميم العقد أولًا ووصف code-first مولّد

1. **نموذج هذا المستودع هو code-first في وصف OpenAPI:** springdoc يولد وصفًا آليًا من وحدات الكود/DTOs (107 مسارات في baseline المقيس). يُعرّف المنتج والهندسة العملية وسلوكها وAC قبل البرمجة، ثم يكون وصف OpenAPI المولد من الكود هو المخرج الآلي القانوني الذي تحرسه بوابة التوافق الرجعي الحالية. لا تُدار نسخة YAML يدوية ثانية بالتوازي مع وصف springdoc.
2. **التسمية والأخطاء:** تسمية الموارد/الحقول تتبع العقد الفعلي (أمثلة `posts`, `businesses`, `local-knowledge`, `official-messages` هي أسماء منطقية حتى يثبتها fit-gap). يستخدم عقد الأخطاء المعياري RFC 9457 (`application/problem+json`) مع `type` مستقر ورسائل لا تكشف تفاصيل داخلية؛ لا تنشأ صيغة أخطاء موازية.
3. **التوسيع فقط:** إضافة حقول اختيارية ومسارات جديدة مسموحة؛ تغيير دلالة أو حذف = قرار إصدار معلن (فصل إهمال عن إنفاذ — خطة موحدة §8.3).
4. **التكرار الآمن ليس مرشح Spring جاهزًا افتراضيًا:** طبّق idempotency حيث يمكن أن يؤدي retry إلى إنشاء سجل/تحصيل/انتقال حالة مكرر، بعد إثبات وجود حل قائم في fit-gap. يجب أن يحدد عقد العملية نطاق المفتاح وربطه بالفاعل والعملية وبصمة الطلب، ونتيجة الطلب الأول، وسياسة الاحتفاظ، والتعامل مع الطلبات المتزامنة وإعادة الاستجابة. إن استُخدم `Idempotency-Key` في REST فهو عقد تطبيق مطلوب تنفيذه واختباره وتوثيقه، وليس خاصية تُنسب تلقائيًا إلى Spring MVC أو مرشح رسمي غير محدد؛ المفاتيح الفريدة وقواعد المجال قد تكون الأنسب لبعض العمليات.
5. **الترقيم (Pagination):** keyset/cursor في كل قوائم الإسقاط (تغذية/بحث/إشعارات) بلا إزاحة — يحمي AC-02-01 (استقرار الترتيب بين الصفحات).

## 4. الهوية والثقة والأدوار (المرحلة 1 — موجة C-1)

**المقيس:** `UserRole {CONSUMER, PROVIDER, ADMIN}` + `ReviewerBadge`/`ReviewerTrustScore` (مراجعة المجتمع) + `MembershipVerificationState` + منفذا `NeighborhoodVerificationProvider` و`NeighborhoodTrustLookupPort` في shared + أحداث `MembershipVerificationGrantedEvent`/`UserRoleChanged`.

**المستهدف (يحكمه JT-12 + JT-01):**

1. **وقائع تحقق منفصلة عن الهوية:** جدول `verification_facts` (النوع: LOCAL_MEMBERSHIP / BUSINESS_OWNERSHIP / PROFESSIONAL / INSTITUTIONAL_DELEGATION؛ الحالة؛ الأدلة في مخزن سري لا في الملف العام) — كل نوع يثبت واقعة محددة فقط (رحلات §14.3). لا ترقية ضمنية: امتلاك واقعة لا يغير `UserRole` ولا يمنح صلاحية خارج نطاقها.
2. **قرار D-03 (الأدوار المتعددة):** ترحيل آمن من `UserRole` الأحادي إلى أدوار مستمدة من الوقائع والملكيات (المسار الأقل كلفة: جدول اعتمادات أدوار مرجعي يقرأه `method-security` القائم) — التصميم التفصيلي بعد fit-gap مع قواعد `@PreAuthorize` المقيسة في الوحدات.
3. **قرار D-02 (العضوية الموثقة):** واحدة نشطة (سلوك الخدمة الحالي) أم متعددة — ترحيلة واحدة تحسمه، والأحداث القائمة (منح/سحب) تُستهلك من الإسقاطات.
4. **اختبار سلبي إلزامي لكل فعل:** مصفوفة المرفوض (غير موثق، دور خاطئ، مالك خاطئ، حي خاطئ، حالة غير مؤهلة) في اختبارات التكامل — قاعدة «إخفاء الزر ليس أمنًا» (رحلات §22).

## 5. المؤسسات والرسائل الرسمية (P0 → المرحلة 4)

**الخطوة C-0 (بوابة كل ما بعدها):** توصيل `marketplace-institutions` — مسودة **#525** قائمة بالفعل: إضافته إلى `<modules>` + اعتماد `marketplace-app` + اختبار Modulith للحدود + دخان إقلاع مع الوحدة. تُراجع المسودة وتُستكمل بواباتها، لا تُستنسخ موجة موازية.

**ثم C-4 (يحكمه JT-10):**

1. **دورة حياة الرسالة:** DRAFT/REQUESTED → REVIEW_REQUIRED أو AUTHORIZED → ACTIVE → CORRECTED / WITHDRAWN / EXPIRED — منفصلة عن العاجل، واختيار التصنيف لا يمنح الصلاحية (AC-10-01).
2. **مصفوفة التفويض (رحلات JT-10 §12.4):** `institutional_delegation` (الجهة × الفاعل × نطاق جغرافي × نوع الرسالة × عاجل أم لا) — الناشر مخول بالسجل لا بالاسم.
3. **الاستهداف الجغرافي:** عبر `geo` + PostGIS (وفق docs/postgis-integration-plan.md القائم — قرار D-07 للعربية ينسحب على فهارس البحث الجغرافي) — التغطية تُختبر بحدود (AC-10-02).
4. **لا قناة إشعارات ثانية:** الرسائل الرسمية حدث أعمال عادي يستهلكه `notifications` القائم (رحلات JT-10 §12.1.8) — البث عبر كتالوج §7 هنا.
5. **التصحيح/السحب ينشر إبطالًا** لكل الإسقاطات (تغذية/بحث/AI) — الحالة المنتهية لا تُعرض نشطة أبدًا (AC-10-04، ومقيس أصلًا في V162 ‏`ai_withdrawn_sources`).

## 6. البحث والذكاء الاصطناعي (المرحلة 5 ثم 10)

**مرجع مقارنة منتج/معمارية:** [community-platform-nextdoor-benchmark.md](community-platform-nextdoor-benchmark.md). يلزم اختبار JT-18 (الخريطة والنطاق) وJT-19 (الأخبار/الناشر) ضمن مسارات البحث لا افتراض أن وجود endpoint بحث يغطيهما.

**المقيس عند رأس الخطة:** `search` (25 ملفًا) + `ai` (33 ملفًا، مطبوع ومنشور من #522)؛ توحيد توجيه بحث AI من #524 مدمج في `main` منذ `fdb6295a`. PR #529 مفتوح (رأس `da3660f6`) لبحث PostgreSQL العربي وأنواع سؤال/طلب؛ V166–V169 محجوزة في لقطة هذا PR وتحتاج إعادة قياس قبل الدمج.

**خطة التنفيذ:**

1. **عقد البحث الموحد (C-5):** يملك `search` عقد النتائج والفلاتر والنطاق والأهلية وadapters لكل مجال. اتجاه توحيد بحث AI عبر العقد القانوني الذي حمله #524 موجود في baseline المدمج ويجب التحقق من كوده الحالي؛ يراجع PR #529 المفتوح على العقد نفسه قبل الدمج، من دون كتابة مسار جانبي أو إعادة تنفيذ #524. كل قرار يثبت بمعاينة code diff والاختبارات الحالية.
2. **العربية (قرار D-07):** توحيد الألف/الهمزة/الياء/التشكيل في طبقة قاعدة البيانات (pg_trgm + توحيد مقيس — postgresql.org/docs/current/pgtrgm.html) مع مجموعة تقييم عربية موسومة مختبرة على AC-04-03؛ وجود كائن الإعداد يُتحقق منه فعليًا في قاعدة اختبار الإصدار (AC-04-04).
3. **سلم الذكاء الستّي (خطة موحدة §9):** (1) حتمي → (2) محرك بحث → (3) قرارات Jev/TypeSafe المهيكلة → (4) نموذج رخيص → (5) نموذج قوي → (6) درجات تقييم تحرس الجميع. القاعدة المقيسة من #522 تسري: **المسارات المطبوعة (chat HTTP contract + أدوات البحث) تُقرأ فقط من العقود القانونية؛ الأهلية والرؤية قبل النموذج وبعد الاسترجاع؛ الخاص/المخفي/المسحوب لا يدخل سياق النموذج (V162 يقيس المسحوب بالفعل).**
4. **المزود الحي:** تفعيل لاحق بمفاتيح بيئة فقط (قاعدة الأسرار §10) — `SPRING_AI_MODEL_CHAT` حاليًا `none` في الإنتاج وهذا هو السلوك الصحيح حتى قرار التفعيل.
5. **OpenSearch (قرار D-06):** خلف بوابة قياس التكلفة/الجودة/التشغيل مقابل خط أساس PostgreSQL مقيس — لا فهرسان متداخلان بلا مبرر مثبت (رحلات JT-04 §6.5).
6. **ترتيب تعلمي (المرحلة 10):** بعد خط أساس حتمي + مجموعة تقييم + بيانات عرض/تفاعل (خطة موحدة §10) — مع اختبار مثبت أن غياب التفاعل لا يصبح إشارة سلبية، وملف الاهتمامات قابل لإعادة البناء والحذف (بوابة المرحلة 10).

## 7. التغذية والإشعارات والأحداث (المراحل 3 و7)

### 7.1 النطاق الجغرافي والخريطة (JT-18)

- المصدر المالك لحدود الأحياء/مناطق الخدمة يحدد المرجعية والإصدار؛ الخريطة إسقاط عرض وليست مصدر صلاحية.
- افصل أهلية رؤية مجتمع خاص عن تغطية مصدر/خدمة وعن نطاق الاستكشاف المختار. لا يُستنتج أي منها من موقع GPS وحده.
- قبل PostGIS أو خدمة جغرافية مستقلة أو مزود خرائط، نفّذ fit-gap على الجداول والامتدادات والاستعلامات الحالية، ثم اختبر حدود المضلع وتداخل المناطق ودقة الموقع والزمن والكلفة. لا يعتمد نصف قطر 2.5–4 ميل ولا Atlas/Mapbox من دراسة المنافس.
- كل علامة تشير إلى نوع السجل ومعرّفه الأصلي وحالته وتوقيته؛ التصفية عند المصدر/الخادم تمنع إسقاط محتوى خاص، ويجب إبطال العلامات المتأخرة بعد السحب/الحذف. عند فشل الخريطة، تبقى قائمة نتائج نصية قابلة للاستخدام.

### 7.2 الأخبار المحلية ومصادر النشر (JT-19)

- افصل رابط خبر شاركه عضوًا عن مادة ناشر معتمد، وعن رسالة جهة عامة، وعن تنبيه عاجل. لكل نوع مالك وصلاحيات وحالة وتدفق نشر مختلف.
- يتطلب أي تجميع/استيراد مقالات قرار D-30: مصدر الناشر، التفويض/الملكية، حقوق إعادة التوزيع والإسناد، نطاق التغطية، استراتيجية التحديث والتصحيح والسحب. لا تُخزّن أو تعِد نشر نص كامل دون حق مثبت.
- البحث والتغذية تحتفظ بمرجع المقال الأصلي ومصدره وتاريخه ونسخة/حالة الإسقاط. تحديث المصدر أو سحب المقال يعطل العرض القديم؛ لا تُعامل مشاركة الرابط كتوثيق للناشر.
- ملخص AI ليس مصدرًا بديلًا: لا يستخدم إلا محتوى مأذونًا، مع إحالات للمصادر، وfallback صريح إذا تعذر تحميل الأصل.

يُربط تطبيق الخريطة والأخبار بموجات C-2/C-3/C-5/C-7/C-11 بحسب الجاهزية، وتضاف اختبارات ACC-MAP-GEO وACC-LOCAL-NEWS قبل إعلان الرحلتين مكتملتين.

### 7.3 التغذية والاكتشاف الموضوعي (C-3 — تحكمها D-05 وD-31)

- **fit-gap قبل وحدة جديدة:** افحص `NeighborhoodListingEventListener` والعقود/المستمعين الحاليين ومسارات العرض والبحث. D-05 يقرر هل تنشأ `marketplace-feed` تنسيقيًا أم يوسع الموجود؛ D-31 يحدد عقد الصفوف وtaxonomy. لا يُنشأ جدول منشورات أو خدمة مستقلة لكل صف/موضوع.
- **السجل الأصلي هو الحقيقة:** كل بطاقة/وثيقة فهرسة تمثل مرجعًا إلى النوع ومعرف السجل الأصلي وإصداره/توقيته. لا تُنسخ المنشورات أو المراجعات أو ملفات الأعمال لبناء الصفوف. مالك المجال يعيد فحص الحالة والصلاحية عند الترطيب وعند فتح التفاصيل.
- **أبعاد مستقلة:** غرض المحتوى، موضوع/موضوعات، النطاق الجغرافي، مصدر/علاقة المتابعة، دورة الحياة، الاستعجال/التفويض، والصفة التجارية. تبقى `PostCategory` الحالية في خط الأساس المقيس `GENERAL/CLASSIFIED/LOST_FOUND/RECOMMENDATION`; `QUESTION/REQUEST` ليستا ضمن ذلك الخط الأساسي و#529 يحتاج إعادة قياس/مراجعة. لا تُستخدم قيمة enum الحالية بديلًا عن taxonomy متعددة الأبعاد.
- **ترتيب التنفيذ:** الأهلية الحتمية (النشر والإشراف والرؤية والصلاحية والنطاق والحالة/السريان والتفويض) → الاسترجاع من adapters المصادر عبر عقد البحث → تكوين الصفوف وإزالة التكرار → ترتيب حتمي مفهوم في الخط الأساس → إسقاط DTO للعميل. لا يعيد AI تأهيل نتيجة مرفوضة ولا يتجاوز رؤية/عضوية أو تفويض.
- **الأسطح:** Following/«المتابعة» يبقى مسارًا صريحًا من الاشتراكات؛ For You/«لك» مسار منفصل مبرر. الصفوف الموضوعية تلخص عينات مؤهلة وتفتح صفحات كاملة بمرشحات؛ تنبيهات السلامة/الطقس/الانقطاع المؤهلة تظهر في مساحة بارزة مستقلة لا في ترتيب شريط عادي. لا يظهر صف فارغ، وتُضبط عتبة عرضه وفق كثافة المحتوى المؤهل.
- **منع التكرار:** مفتاح المصدر/المعرف الأصلي هو أساس إزالة التكرار، لا تشابه النص فقط. يُمنع التكرار داخل الصف الواحد وإعادة تسجيل impression بسبب retry/page refresh؛ يظل نفس السجل قابلًا للاكتشاف ضمن سياق موضوعي آخر دون إنشاء نسخة. كل impression له تعريف عرض متفق عليه مع العميل، لا يعادل تسليم API.
- **البحث والـAI:** PostgreSQL هو baseline الحالي؛ OpenSearch يظل خيارًا خلف D-06 بعد قياس جودة/زمن/تكلفة/تشغيل. لا يستدعى نموذج لكل منشور؛ يُقيّم نموذج منخفض التكلفة للغموض النصي فقط. `JevModelRouter` لا يمنح سلطة المجال؛ أي structured judgment/routing يحتاج عقد خرج واختبارات مثبتة. ملخص أو توصية متعددة المصادر تتطلب إحالات إلى سجلات فعلية مع تواريخها؛ عند غياب الأدلة يعرض النظام المصادر الخام/الفشل الصريح، ولا يصف نشاطًا بأنه موصى به دون دليل.
- **الثقة التجارية:** المدفوع له وسم ثابت ويظل منفصلًا عن عضوية الثقة والتوصية العضوية؛ لا تخفيه قاعدة ترتيب ولا يُمنح علامة ثقة بشراء موضع.
- **بوابة «لك» المتعلم:** لا يفتح ترتيب تعلمي قبل خط أساس، ومجموعة تقييم عربية، وقياس انحياز الإشارات/غياب التفاعل، ووسيلة تفسير/اعتراض، وقابلية إعادة بناء ملف الاهتمامات/حذفه (D-13/مرحلة 10).

### 7.4 كتالوج أحداث الأعمال (C-7 — يحكمه رحلات §23)

لكل حدث في الكتالوج: مستلم مؤهل + قناة + تفضيل + إلحاح + idempotency — يجرد في جدول قرار يقره المالك قبل التنفيذ (نفس منهج V158/V159/V164/V165 المقيس لأنواع التفضيلات):

`post.replied · post.mentioned · post.resolved · group.join-requested/decided · event.updated/cancelled · service-inquiry.received/updated · market-item.state-changed · official-message.published/corrected/withdrawn/expired · verification.state-changed · report.decided · recommendation.linked · knowledge.stale-detected/published/withdrawn · digest.daily-business`

- التوجيه عبر `notifications` القائم (قنوات inbox/بريد/WebSocket) — push بعد قرار D-10 (FCM/APNs رسميًا: firebase.google.com/docs/cloud-messaging · developer.apple.com/documentation/usernotifications).
- **at-least-once مع خفض تكرار مستهلك** — لا ادعاء exactly-once (رحلات §25.2) — ومفتاح idempotency يمنع الإشعار المكرر (AC-11-02).
- Quiet hours وdigest وفق D-26 — تجميع استفسارات الأعمال أولاً (فجوة P5).

## 8. حقوق البيانات والخصوصية الهندسية (C-1 — سد فجوة المراجعة)

الامتثال قرار قانوني مؤهل (D-15) يحدد نطاق الأسواق والقوانين المنطبقة لكل سوق مع مستشار مؤهل؛ لا يفترض هذا الدليل ولاية قضائية سعودية أو أوروبية من نفسه. الهندسة توفر القدرات اللازمة بعد توثيق المتطلب القانوني:

1. **تصدير بياناتي:** مهمة غير متزامنة (قائمة قائمة في `platform-infra`) تجمع بيانات المستخدم من كل المجالات عبر منافذ SPI (لا استعلام متقاطع) → ملف موقّت بمدة صلاحية معلنة → تنزيل بضغط مالك مرة واحدة.
2. **التصحيح:** مسارات تعديل الملف والبيانات الشخصية بصلاحية صاحبها + تدقيق Envers (قائم مقيسًا في قواعد المستودع).
3. **الحذف/الإغلاق:** قدرة حذف/إغلاق الحساب وإبطال الجلسات موجودة تقنيًا في baseline بعد #511؛ القرار D-20 المتبقي يخص أثر المحتوى العام (منشورات/توصيات/معرفة محلية) والاحتفاظ والتجهيل أو الإزالة وفق سياسة يقرها المالك وتراجع قانونيًا. لا تبنِ واجهة/endpoint حذف موازية؛ نفّذ fit-gap للقدرات الحالية قبل توسيعها.
4. **خصوصية القياس:** المقاييس المسموحة فقط (رحلات §25.3)؛ سجل البحث مجهول الهوية للتقييم (رحلات §25.4)؛ لا حقول خام حساسة «لمجرد القدرة على جمعها».

## 9. الأمان الهندسي (يعمل عبر كل الموجات)

- **المصادقة قائمة ومقيسة:** OIDC + PKCE (edge) + JWT بمفتاح `marketplace-jwt-r3` — **دوران المفتاح قبل 2026-12-08** (التزام تشغيلي مفتوح من سجل النشر) عبر نفس نمط r2→r3 الموثق.
- **الأسرار:** Gitleaks (سياسة high/critical) مقيس في CI؛ المفاتيح متغيرات بيئة حصرًا (قاعدة مستودع مسجلة بعد حادثة المفتاح المصححة)؛ أي سر يظهر = إبطال فوري لا حذف كوميت فقط.
- **الصلاحيات:** `method-security` مكتمل من #511 (مقيس في عنوان الدمج) — كل فعل جديد يبدأ باختباراته السلبية (§4 هنا).
- **حد المعدل (429):** حد لكل مستخدم/نطاق على عمليات الكتابة الحساسة والبحث — يظهر للعميل برأس إعادة المحاولة (CMP-23).
- **سلاسل الفحوص:** CodeQL + Trivy + snyk القائمة تحرس كل موجة — لا استثناء جديد.
