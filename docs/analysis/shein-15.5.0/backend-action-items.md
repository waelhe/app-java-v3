[الملف الحاكم]: `docs/governance/plans/saleor-dashboard-full-commerce-canonical-plan.md` (D-SALEOR-FULL-001).
[النواة المعمارية]: طبقة الوحدات (§5) + عقد DGS + طبقة البيانات (§7) — **هذا الملف تخطيط فقط، لا كود ولا ترحيل**.
[البند من المصفوفة §14.2]: مطابقة العقد + حدود Modulith (مالك واحد لكل نقطة اتصال).
[أثر على الحدود]: لا تغيير. كل بند يقترح مالكًا من النطاقات القائمة؛ النطاقات الجديدة تُرفع كقرار لا كوحدة ضمنية.
[دين]: لا.

> **قاعدة:** هذا الملف **لا يفتح عملًا**. هو إسقاط للبنود من `e2e-journeys.md` على الجرد المقيس `saleor-458-root-inventory.csv`.
> كل جذر مذكور هنا مأخوذ **حرفيًا** من الجرد مع حالته المقيسة؛ لا اسم مخترع ولا حالة مفترضة.
> تنفيذ أي بند يحتاج كلمة المالك + بوابة الموجة، حسب الخطة الحاكمة.

## 2. العمود الفقري التجاري — P4 (12 بندًا)

### E2E-01 · دورة حياة جلسة الدفع
- **المالك:** `marketplace-orders`
- **الفجوة:** (أ) — `getOrCreateActiveCart` + `addCartItem` قائمة.
- **الجذور:** `checkoutCreate` · `checkoutCustomerAttach` · `checkoutEmailUpdate` (NOT_STARTED) · `checkoutDelete` (INTEGRATED).
- **القبول:** إنشاء جلسة لزائر ثم ربطها بمستخدم لا يغيّر المعرّف؛ الجلسة تنتهي بصلاحية معلنة؛ `checkoutDelete` يُبطلها.
- **سلبي:** مستخدم ثانٍ يقرأ جلسة غيره → `NOT_FOUND`.
- **الموجة:** P4 · **يعتمد على:** —

### E2E-02 · عمق قراءة السلة (فجوة دلالية)
- **المالك:** `marketplace-orders` + `marketplace-pricing`
- **الفجوة:** (أ) — الجذر `checkout` **INTEGRATED** لكن `CheckoutView` المقيس = `id/lines/quantity` فقط بلا سعر/إجمالي/شحن/ضريبة.
- **الجذور:** `checkout` · `checkoutLines` (NOT_STARTED).
- **القبول:** استجابة `checkout` تحمل لكل سطر سعر الوحدة والإجمالي، ومجاميع (subtotal/discount/shipping/tax/total) بعملة الجلسة.
- **سلبي:** سلة بلا عنوان لا تُرجع شحنًا مزيّفًا (`null` معلن، لا صفر كاذب).
- **الموجة:** P4 · **يعتمد على:** —

### E2E-03 · العنوان وطريقة التسليم في الدفع
- **المالك:** `marketplace-orders` + `marketplace-identity` + `marketplace-delivery`
- **الفجوة:** (أ) للعنوان (‏`AccountAddressService` موجود) + (ب) لمناطق الشحن.
- **الجذور:** `checkoutShippingAddressUpdate` · `checkoutBillingAddressUpdate` · `checkoutDeliveryMethodUpdate` · `deliveryOptionsCalculate` (NOT_STARTED) · `shippingZone(s)` (BLOCKED) · `shippingPrice*` (NOT_STARTED).
- **القبول:** عنوان محفوظ → خيارات تسليم بأسعار ونوافذ؛ تغيير العنوان يعيد الحساب.
- **سلبي:** عنوان خارج المنطقة → `NOT_FOUND`/خطأ مجال، لا خيار تسليم وهمي.
- **الموجة:** P4 — **الشريحة الأولى (عنوان فقط) تبدأ فورًا؛ خيارات التسليم محجوبة حتى E2E-19**.
- **يعتمد على:** E2E-19 (للشحن).

### E2E-04 · القسائم على جلسة الدفع
- **المالك:** `marketplace-pricing` + `marketplace-orders`
- **الفجوة:** (أ) — `Voucher`/`VoucherRedemption` + `voucherCreate/Update/Delete` INTEGRATED.
- **الجذور:** `checkoutAddPromoCode` · `checkoutRemovePromoCode` (NOT_STARTED).
- **القبول:** إضافة رمز → خصم معاينة؛ إزالة → إرجاع الإجمالي؛ رمز منتهٍ/غير منطبق → سبب رفض صريح.
- **سلبي:** رمز مستخدم سابقًا بحدّ استخدام واحد → رفض، لا خصم صامت.
- **الموجة:** P4 · **يعتمد على:** E2E-02.

### E2E-05 · إنشاء الطلب من الدفع
- **المالك:** `marketplace-orders`
- **الفجوة:** (أ) — `place()` يقسّم بحسب البائع ويجمّد السعر ويحجز المخزون (مقيس).
- **الجذور:** `orderCreateFromCheckout` · `checkoutComplete` (NOT_STARTED).
- **القبول:** سلة ببائعَين → طلبان مرتبطان بنفس الجلسة، مبالغ مجمّدة، مخزون محجوز، والجلسة تُستهلك مرة واحدة.
- **سلبي:** إعادة الإرسال بنفس مفتاح idempotency → نفس الطلبات، لا تكرار.
- **الموجة:** P4 · **يعتمد على:** E2E-02 · E2E-04.

### E2E-06 · دورة حياة الطلب
- **المالك:** `marketplace-orders` + `marketplace-delivery`
- **الفجوة:** (أ) — `confirm/fulfill/cancel` موجودة.
- **الجذور:** `orderConfirm` · `orderFulfill` · `orderFulfillmentApprove` · `orderFulfillmentCancel` · `orderUpdateShipping` · `orderMarkAsPaid` (NOT_STARTED).
- **القبول:** كل انتقال حالة مسموح مرة واحدة، مع طابع زمني وحدث عام؛ الانتقال غير المسموح → خطأ مجال.
- **سلبي:** `orderFulfill` على طلب غير مؤكَّد → رفض (لا قفزة حالة).
- **الموجة:** P4 · **يعتمد على:** E2E-05.

### E2E-07 · تتبّع الشحنة على العقد
- **المالك:** `marketplace-delivery` + `marketplace-orders`
- **الفجوة:** (أ) — `DeliveryService` يملك التتبّع، والجسر إلى الطلب غير معلن.
- **الجذور:** `orderFulfillmentUpdateTracking` (NOT_STARTED).
- **القبول:** `OrderDetailPkgTrackDelegate` يقابل حقل تتبّع معلن يعيد آخر نقطة + ETA + رابط ناقل.
- **سلبي:** طلب بلا شحنة → `null` معلن، لا قائمة فارغة مضلّلة.
- **الموجة:** P4 · **يعتمد على:** E2E-06.

### E2E-08 · قراءة وكتابة الدفع
- **المالك:** `marketplace-payments` + `marketplace-ledger`
- **الفجوة:** (أ) — `createOrderIntent` · `processIntent` · `confirmIntent` · `processWebhookEvent` موجودة.
- **الجذور:** `payment` · `payments` · `transaction` · `transactions` · `paymentGatewayInitialize` · `transactionInitialize` · `transactionProcess` · `transactionEventReport` (NOT_STARTED).
- **القبول:** نيّة → تهيئة بوابة → معالجة → webhook موقّع → طلب مدفوع + قيد دفتر واحد.
- **سلبي:** توقيع خاطئ → رفض 401/خطأ أمني، ولا تحديث حالة.
- **الموجة:** P4 · **يعتمد على:** E2E-05.

### E2E-09 · الالتقاط والإبطال والاسترداد
- **المالك:** `marketplace-payments` + `marketplace-ledger`
- **الفجوة:** (أ) — `refundPayment(amount)` + `autoRefundByOrder` موجودة.
- **الجذور:** `paymentCapture` · `paymentVoid` · `paymentRefund` · `orderRefund` (NOT_STARTED).
- **القبول:** استرداد كامل وجزئي بمفتاح idempotency ثابت (`StableRefundScope.forReturn`)؛ القيد يعكس المبلغ فقط.
- **سلبي:** استرداد يتجاوز الملتقَط → رفض حسابي، لا رصيد سالب.
- **الموجة:** P4 · **يعتمد على:** E2E-08.

### E2E-10 · الإرجاع والاستبدال على العقد
- **المالك:** `marketplace-orders`
- **الفجوة:** (أ) — `OrderReturnsService` كامل (request/approve/reject/receive/complete + `replacementOrderId` + `restockLines`).
- **الجذور:** `orderFulfillmentReturnProducts` · `orderGrantRefundCreate` · `orderGrantRefundUpdate` · `orderFulfillmentRefundProducts` · `returnReasonReferenceClear` · `refundReasonReferenceClear` (NOT_STARTED).
- **القبول:** إرجاع جزئي بكمية → استرداد محسوب + إعادة مخزون؛ استبدال → طلب بديل مرتبط؛ استرداد كقسيمة → `voucherCreate` بصلاحية.
- **سلبي:** كمية تتجاوز المسلَّم → رفض؛ إرجاع مكرر لنفس السطر → رفض.
- **الموجة:** P4 · **يعتمد على:** E2E-06 · E2E-09.

### E2E-11 · الفواتير
- **المالك:** `marketplace-orders` (+ `marketplace-ledger` للترقيم)
- **الفجوة:** (ج) — **لا صنف `Invoice` في الشجرة (مقيس: صفر فئة)**، والجذور غير محجوبة.
- **الجذور:** `invoiceRequest` · `invoiceCreate` · `invoiceSendNotification` · `invoiceDelete` · `invoiceUpdate` (NOT_STARTED).
- **القبول:** طلب فاتورة → ملف ثابت (PDF) + رقم تسلسلي + إرسال بالبريد + إعادة تنزيل.
- **سلبي:** طلب فاتورة لطلب غير مدفوع → رفض.
- **الموجة:** P4 · **يعتمد على:** E2E-06 · E2E-08.

### E2E-12 · الطرق المحفوظة والدفع بنقرة (OCB)
- **المالك:** `marketplace-payments`
- **الفجوة:** (ج) — **لا صنف طريقة دفع محفوظة (مقيس: صفر فئة)**؛ الجذور موجودة غير محجوبة.
- **الجذور:** `paymentGatewayInitializeTokenization` · `paymentMethodInitializeTokenization` · `paymentMethodProcessTokenization` · `storedPaymentMethodRequestDelete` (NOT_STARTED).
- **القبول:** حفظ طريقة عند الدفع → ظهورها لاحقًا → دفع بنقرة (تخطّي الكاشير) → إبطال يمنع الاستخدام.
- **سلبي:** رمز مُبطل → رفض واضح وإعادة توجيه للكاشير، لا فشل صامت.
- **الموجة:** P4 · **يعتمد على:** E2E-08 · قرار أمني (تخزين رموز الدفع).

## 7. تعريف الإنجاز لكل بند (مقيس، لا وصفي)

لكل بند، الإنجاز = الشروط السبعة مجتمعة:

1. الجذر معلن بالتوقيع الحرفي من الجرد (لا إعادة صياغة).
2. منفّذ عبر SPI مالك النطاق (لا استعلام مباشر عبر حدود الوحدة).
3. اختبار DGS إيجابي.
4. اختبار سلبي للتفويض (وصول غير المالك → `NOT_FOUND`/رفض).
5. اختبار idempotency إن كانت العملية مالية.
6. صف الجرد محدّث إلى `INTEGRATED` + عمود `dashboard_e2e` مملوء (اليوم **458 صفًا فارغًا** — بوابة P7 لا تمرّ بصدق قبله).
