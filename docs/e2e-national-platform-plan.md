# خارطة المنصة الوطنية متعددة الأدوار — تجربة مستخدم كاملة End-to-End

> **وثيقة حاكمة مرشّحة** — صيغت بأمر المالك (2026-10-07) وحُفظت بدفع فوري لحمايتها من فقدان الجلسة.
> **الحالة**: فرع `docs/e2e-journey-plan` — مدفوعة **بلا دمج**. الدمج بكلمة المالك حصراً (§14.3).
> **علاقتها بالوثائق القائمة**: هذه الخارطة هي الترجمة الرحلية (journey-first) لرؤية المنصة متعددة الأدوار؛ وتُصالَح مع خطة #503 (`docs/unified-platform-plan` — بيد المالك، غير مدموجة) عند قراره: إما أن تحل مكانها أو تمتد منها. قرار المصالحة للمالك وحده.

## 1. رؤية المالك (كما وُصفت حرفياً 2026-10-07)

منصة **متعددة الأدوار والوظائف والمزودين**: نظام مجتمعي على مستوى البلد والمدينة والأحياء (نمط Nextdoor العالمي) يعتمد **التوثيق والتوصية** لانضمام الأعضاء، يتكون من:

1. **قسم المجتمع**: جديد/شائع • منشورات (سؤال، طلب، توصية، استطلاع، مفقودات) • **إعارة مدفوعة** • الأخبار والبث • نشاطات ومبادرات • مجموعات • **مؤسسات** • تفاعل/تعليق/اتصال/محادثة/تواصل.
2. **قسم السوق**: المنتجات • المستعمل • العقار • السيارات • الخدمات (مهني، علمي) • الوظائف.
3. **قسم دليل الأعمال**: مراجعة، تقييم، ملف تجاري.
4. **قسم «تعرف على»**: دليل معلومات متكامل عن الحي وسكانه **يبنيه المجتمع**.
5. **لوحة تحكم متقدمة**: التغيير على المنصة **من اللوحة لا من الكود** • UI dash • نظام تحديثات • أحدث إصدار.
6. **نظام إشعارات متطور**: لكل قسم وجزء وموضوع.
7. **منتجات وخدمات المجتمع ودليل الأعمال تظهر مباشرة** كمنتجات وخدمات في السوق.
8. **البحث**: حسب تصنيف وعلى مستوى المدينة (الأحياء) والحي.

**قيد التصميم الأعلى (أمر المالك 2026-10-07، آخر الجلسة): «تأكد أن الخطة تصمم تجربة المستخدم الكاملة end to end»** — كل موجة في هذه الخارطة شريحة رأسية تُسلّم رحلة مكتملة، لا طبقة خلفية تنتظر واجهة.

**متوسط المنصة: ~70/100 • صفر TODO في الـ22 وحدة • عيوب مقيسة تصلح أولاً (الموجة 0):**
1. كاش `search-results-v4` ميت مقابل `v5` الحي في GeoService + RealestateService (بيانات بحث قديمة ساعة بعد تعديل موقع/عقار).
2. عدّاد غير المقروء في المحادثة يحسب رسائل المرسل نفسه.
3. لا محدد معدل على إرسال الرسائل + لا idempotency للرسالة.
4. حدث `BookingConfirmedEvent` ميت (منشور بلا مستمع) + تعارض 404/403 في توثيق الجلب.
5. النزاعات: صفر أحداث (الطرف الآخر لا يُخبَر) + الاسترداد الجزئي مدعوم بالمنفذ وغير مفعّل.
6. لا حذف إشعار ولا «تعليم الكل كمقروء».

## 3. تجربة المستخدم أولاً (المحور الحاكم)

### 3.1 الأدوار الستة

| الدور | رحلته المركزية |
|---|---|
| الزائر | اكتشاف بالبحث/التصنيف/الحي (SEO) → الانضمام |
| العضو | توثيق الحي بالتوصية → نشر/تفاعل/استعارة/شراء |
| البائع/المزوّد | ملف تجاري → منتجات وخدمات → طلبات → سحب الأرباح |
| المؤسسة | تسجيل موثّق → ملف → خدمات مباشرة → إشعاراتها |
| المشرف | طوابير → قرارات → سلامة المحتوى |
| مدير النظام | لوحة التحكم: كل تغيير بلا كود |

### 3.2 مراحل الرحلة التسع وحالتها اليوم

| المرحلة | الحالة | من يغلقها |
|---|---|---|
| 1 اكتشاف (بحث/تصنيف/حي) | 🟡 بحث قوي بلا وجوه تصنيف ولا فهرسة مجتمع | A |
| 2 انضمام وتوثيق | 🔴 لا توصية عضو (Nextdoor)، لا توثيق بريد، لا استعادة كلمة مرور | 0+A+B |
| 3 دخول وجلسة | 🟢 OIDC + جلسات حتى الخروج (PR #504) | — |
| 4 استخدام القسم | 🔴 لا واجهة استخدام إطلاقاً | كل موجة بشريحتها |
| 5 تواصل ومحادثة | 🟡 1:1 نصي فقط، لا إشعار وصول رسالة | B |
| 6 دفع | 🟢 Stripe قوي؛ لا سلة/طلب بضائع | C |
| 7 إشعار | 🟡 3 قنوات بلا Push/عربية/موضوعية | A→ |
| 8 تتبع ومراجعة | 🟡 تقييم قوي؛ لا تتبع طلب/شحن | C |
| 9 إدارة وتغيير | 🔴 مفتاحا إعدادات فقط | A |

### 3.3 نقاط الانقطاع السبع (تكسر أي رحلة اليوم)

لا واجهة • لا عربية خارج رسائل الخطأ • استعادة كلمة المرور غائبة (قالبها نائم) • توثيق البريد غائب • إشعار «وصلتك رسالة» غائب • Push غائب • الانضمام بالتوصية غائب.

### 3.4 الرحلات المرجعية الثلاث

**رحلة 1 — «عضو جديد يوثّقه جاره» (روح Nextdoor):** وصول من رابط حيّه → تسجيل + توثيق بريد فوري → طلب انضمام لحيّه → أعضاء موثّقون يوصون به (عتبة قابلة للضبط من اللوحة) → تفعيل + إشعار ترحيبي Push/بريد (إيقاظ قالب welcome النائم) → خلاصة الحي جديد/شائع → نشر توصية/سؤال بتعليقات مترابطة ومنشنات → استعارة أداة بإجرة عبر مسار حجز+دفع موجود → تقييم يُحسب في ثقة الجار.

**رحلة 2 — «شراء منتج من متجر الحي» (أمازون البضائع):** اكتشاف بالحي/التصنيف → صفحة منتج (متغيرات: مقاس/لون) → سلة → دفع Stripe → إنشاء طلب → إشعارات كل تغيير حالة → تتبع الشحن → تسليم → تقييم → رصيد البائع → سحب أرباحه.

**رحلة 3 — «مؤسسة في دليل الأعمال»:** تسجيل مؤسسي موثّق → ملف تجاري (صفحة الأعمال 72/100 أساس) → خدمات تظهر مباشرة في السوق والمجتمع → إشعارات موضوعية لكل خدمة → لوحة المؤسسة.

### 3.5 بوابة الرحلة الكاملة (Definition of Done لكل موجة)

لا تُعلن موجة مكتملة إلا باجتياز الأضلاع الخمسة معاً:

| الضلع | معيار القبول |
|---|---|
| 1 الخلفية | API + أحداث + اختبارات (العرف القائم) |
| 2 الواجهة | سطح استخدام يعمل للمستخدم النهائي — لا JSON مكشوف |
| 3 الإشعار | كل حدث يهم المستخدم يصله في قناته (Push من B فصاعداً) |
| 4 البحث والعربية | كل محتوى جديد قابل للاكتشاف ومُعرَّب |
| 5 اللوحة | كل إعداد جديد للموجة يُدار من لوحة التحكم بلا كود |

**+ اختبار رحلة آلي** لكل موجة (على نمط الـIT الذهبي): سيناريو كامل بيد مستخدم حقيقية من أول خطوة لآخرها.

## 4. الأقسام ↔ الواقع ↔ المطلوب

### 4.1 قسم المجتمع (الأقرب للاكتمال)

| البند | الواقع | المطلوب |
|---|---|---|
| جديد/شائع | زمني فقط | موجتان: زمني + ترتيب بتفاعلات (فلسفة ranking_score القائمة) |
| منشورات: سؤال/طلب/توصية/استطلاع/مفقودات | توصية+مفقودات+استطلاعات (V100) موجودة | ترقية الأنواع لأصناف أولى + «سؤال» و«طلب» |
| إعارة مدفوعة | غير موجودة | **إعادة استخدام مسار الحجز+الدفع القائم** (أرخص بند تجاري) |
| الأخبار/البث | غير موجودة | نوعان جديدان + بث إداري |
| نشاطات ومبادرات | الفعاليات+RSVP موجودة (V83) | + «مبادرات» (فعالية مستمرة بجهة منظمة) |
| مجموعات | موجودة (V91) | اكتمال ضمن موجة المجتمع |
| مؤسسات | غير موجودة | وحدة جديدة `marketplace-institutions` |
| تفاعل/تعليق/محادثة | تعليق/تفاعل/محادثة 1:1 | خيوط + تحرير + منشن + إشعار رسالة + مرفقات |

### 4.2 قسم السوق (الأكبر بناءً)

| البند | الواقع | المطلوب |
|---|---|---|
| المنتجات | سلة/طلبات/مخزون/متغيرات = صفر | **وحدة `marketplace-orders`** فوق آلة payment-intents والدفتر القائمتين (إضافة لا هدم) |
| المستعمل | لوحة سوق الحي (V90) | ترقية لقسم عام ببحث وفلترة |
| العقار | عمق جيد (15 حقلاً + PostGIS) | تاريخ أسعار + جولات |
| السيارات | غير موجودة | تصنيف «مركبات» بخصائص (يعتمد على قيم الخصائص) |
| الخدمات (مهني/علمي) | خدمات البائعين (V96) | شجرة تصنيف + ظهور في السوق |
| الوظائف | صفر | وحدة جديدة `marketplace-jobs` |
| ظهور منتجات/خدمات المجتمع والدليل مباشرة | غير موجود | جسور نشر تلقائية إلى سطح السوق |

### 4.3 قسم دليل الأعمال

مراجعة/تقييم: **reviews 85/100** (اتجاهان+إشراف+أصوات+مضادة إساءة) — أقوى وحدة منتج. الملف التجاري: صفحة أعمال موجودة (ساعات/خدمات/مناطق/JSON-LD/إحصاءات). المطلوب: هيكل الدليل (تصنيفات دليل + مطالبة ملكية + تجميع كل البائعين/المؤسسات في سطح واحد) + تقييم متعدد الأبعاد (اختياري).

### 4.4 قسم «تعرف على»

وحدة جديدة `marketplace-knowledge`: ويكي الحي الذي يبنيه المجتمع (سكان، تاريخ، خدمات، أماكن) بتحرير مجتمعي خلف طابور موافقة (تمديد طابور الإشراف القائم). كل صفحة معلّقة على عقدة Geo (الشجرة 4 مستويات حتى الحي موجودة).

### 4.5 لوحة التحكم والتغيير بلا كود

وحدة جديدة `marketplace-console`: منصة تهيئة زمن-التشغيل — أعلام ميزات، تصنيفات، ترتيب/إظهار الأقسام، كتل واجهة (CMS)، حدود معدل، عتبات التوصية — كلها من اللوحة. الأساس القائم: `system_settings` (V84) بمفتاحين فقط. + نظام إصدارات (سجل + إعلان «أحدث إصدار» من اللوحة) + UI dash.

### 4.6 الإشعارات والبحث

- **الإشعارات**: من مصفوفة 9 أنواع×3 قنوات إلى **اشتراكات موضوعية** (قسم→نوع→حي→موضوع) + Push (FCM/Web Push) + قوالب عربية + هضم/ساعات هادئة.
- **البحث**: وجوه تصنيفية + نطاق البحث بحي/مدينة (شجرة Geo + PostGIS قائمان) + فهرسة محتوى المجتمع (غائبة) + لاحقاً تحليل عربي.

## 5. الوحدات الجديدة الخمس

| الوحدة | دورها | تعتمد على |
|---|---|---|
| `marketplace-orders` | السلة→الدفع→الطلب→الشحن→المخزون→المتغيرات | payments + ledger + catalog |
| `marketplace-jobs` | لوحة وظائف: نشر/تقديم/حالة | identity + messaging |
| `marketplace-institutions` | مؤسسات الحي بملفات موثقة | geo + community verification |
| `marketplace-knowledge` | ويكي «تعرف على» | geo + طابور الإشراف |
| `marketplace-console` | الحوكمة: تهيئة زمن-التشغيل + CMS + أعلام + إصدارات | system_settings القائمة |

**والتوسعات**: catalog (قيم خصائص+شجرة+متغيرات) • community (أنواع+شائع+أخبار+إعارة) • search (وجوه+نطاق حي+فهرسة مجتمع) • notifications (موضوعية+Push) • booking (سياسات+إعادة جدولة) • availability (تعديل/حذف+مناطق زمنية) • disputes (أحداث+أدلة+جزئي+SLA) • messaging (إيصالات+مؤشرات+حضور+مرفقات) • identity (استعادة+توثيق بريد+انضمام بالتوصية).

## 6. خارطة الموجات (كل موجة = رحلة مكتملة)

| الموجة | الرحلة التي تكتمل | أبرز المحتوى |
|---|---|---|
| **0 — إصلاحات** | «لا رحلة تنكسر» | العيوب الستة المقيسة + استعادة كلمة المرور + توثيق البريد + إشعار وصول رسالة |
| **A — أساس الحوكمة** | «المدير يقود والزائر يجد» | وحدة console + التهيئة بلا كود + شجرة التصنيفات + وجوه البحث ونطاق الحي + إشعارات موضوعية + **أول UI حقيقي (اللوحة)** |
| **B — المجتمع الكامل** | رحلة العضو 1 كاملة | أنواع المنشورات الخمسة + شائع/جديد + أخبار/بث + مبادرات + مؤسسات + إعارة مدفوعة + خيوط/تحرير/منشن + **واجهة المجتمع + Push** |
| **C — السوق الكامل** | رحلة الشراء 2 كاملة | وحدة orders + السيارات + الوظائف + ترقية المستعمل + منتجات مباشرة + **واجهة المتجر (سلة→دفع→تتبع) + إشعارات الطلب** |
| **D — الدليل والمعرفة** | رحلة المؤسسة 3 + «تعرف على» | هيكل دليل الأعمال + مطالبة ملكية + وحدة knowledge + **واجهات الدليل والويكي** |
| **E — الصقل العالمي** | السلاسة | أداء، SEO أعمق، ساعات هادئة/هضم، تقييم متعدد الأبعاد، iCal، KYC بمزوّد |

**ترتيب تبعي مقترح** (0→A→B→C→D→E)؛ **المسار النهائي يحدده المالك** (قد يعيد الترتيب — البنية تتحمل). أول إصدار مرئي للمستخدمين من نهاية A (اللوحة) ثم B (المجتمع).
